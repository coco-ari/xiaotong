# 本轮评审与实施取舍

整理日期：2026-10-13。详细来源、查证范围、热度证据、评分和复用条件保存在 [catalog.json](catalog.json)。本文件解释为什么保留某些原则、为什么没有把截图中的所有动效都加入项目，以及实际应用到了哪里。

## 什么值得收录

本轮对 55 条记录逐项评审，按 URL 去重为 52 个地址，按同作者／机构关系合并为 31 个来源族。50 条记录已取得正文或明确范围的内容；“部分已读”不代表读完仓库的全部技能与示例。4 条资料标为待读，另有 1 条只取得搜索摘要、无法支撑质量判断的提示词包被排除。Apple、Material 和受阻论坛条目没有被当作已读权威依据。

最终保留 30 条原创提示词。来源库同时保留未入选的记录，让取舍可追溯；提示词库只展示推荐与有条件收录的方案。同一条来源可支持多个不同任务，但不会通过换标题复制出一批相同提示词。

评分主要考虑以下五点：是否解决明确任务；是否说清触发、状态和完成；是否包含触摸、键盘、减少动态效果与异常边界；是否适合小彤的内容和品牌；实现成本是否值得。提示词推荐门槛为 8 分，有条件收录为 7 分。评分为本轮主观评审，不代表这些方案优于所有替代方案。

## 对截图中的动效逐项判断

截图表现的是一类设计与交互提示词格式。截图作者和完整原始出处未确认，因此本库没有把其内容当作已核验的第三方技能全文转载。以下是结合实际文档与当前项目作出的独立判断。

| 效果 | 结论 | 原因与可用替代 |
| --- | --- | --- |
| 磁吸按钮／控件追随指针 | 当前不采用 | 目标跟随鼠标会增加点击不确定性，移动端也没有同等悬停条件。主要按钮保持位置稳定，使用短促按压与清晰焦点反馈 |
| 速度驱动的液态变形 | 当前不采用 | 文字和金额变形影响识别，阈值、性能与输入边界成本较高。保留稳定尺寸，用颜色和底板传达选择 |
| 多物体碰撞／物理回弹 | 当前不采用 | 缺少对应的真实任务，容易干扰角色、卡片和阅读。需要空间操纵的小游戏可以单独评估 |
| 堆叠卡片缩放滚动 | 当前不采用 | 当前首页需要快速扫描金额、文章和任务，叠压和缩小降低可读性。保留正常文档流与返回滚动位置 |
| 卷曲卡片删除 | 当前不采用 | 删除的可理解性、撤销和键盘等价方式比纸张形变更重要。将明确确认／可撤销作为未来删除操作的基础 |
| 圆形主题揭示 | 有条件候选，当前未实现 | 适合低频主题切换展示，需浏览器回退、减少动态效果和触点范围处理；当前没有必须用该效果解决的主题任务 |
| 滑动选中底板 | 采用 | 直接表达单选筛选关系。按钮语义、方向键、Home／End、即时状态和独立实例标识必须同时实现 |
| 文本展开／批量勾选／拖拽排序 | 收录为特定任务候选 | 分别对应长描述、批量操作和明确顺序任务。当前没有因为效果存在就给所有卡片添加这些交互 |
| 图片共享展开／分层视差 | 有条件候选 | 可用于图片浏览与装饰展示；正文、数据与操作位置保持稳定，提供减少动态效果回退 |
| 手势抽屉 | 增强候选 | 本轮先实现原生模态对话框的底部面板布局。手势关闭、速度判定和滚动冲突尚未实现，不能把二者视为同一完成项 |

此外，Taste 的实验性视觉规则与 Soft 风格不直接套入金融与内容页面；其中很长的过渡、全属性 transition、复杂连续动效需要按任务删减。Luxury 的单色与尖角也不直接替换现有角色气质。静态 CRM 样例可说明结构组织，但不能证明真实数据、键盘操作、性能或完整业务流程已成立。只提供成图的 UI 提示不等于能生成可用网页，因此没有据此认定交互质量。

## 小彤项目的固定条件

首页直接从角色场景开始，以纵向内容卡片进入详情，不额外添加品牌横幅、欢迎标语、底部导航或装饰分类栏。卡片需要优先展示金额、图表、文章标题与任务；视觉统一靠纸白、暖墨、朱红、边界、排版和留白，不依赖反复添加发光或装饰图标。

角色切换遵守已有顺序：资源准备就绪，旧人物退出，背景过渡，新人物与文字按顺序出现。背景允许平滑过渡，人物不能同时叠出，也不能出现空白闪屏。场景心情可以调整光色，但仍属于同一套风格。暂停环境动画与自动轮换时，页面应保留稳定的角色画面。

金融保留本项目的红色收益、绿色亏损约定，并配合文字和数值表达。首轮日收益回放属于明确标注的演示；用户进入详情、操作日期滑杆和返回首页时优先保持状态稳定，不以额外动画拖慢真实选择反馈。

## 验证与维护边界

目录校验覆盖字段、评分范围、ID、引用、统计真实性、文件存在性和安全生成规则，不会替代视觉与使用体验评审。生成脚本不会安装外部依赖、执行来源仓库代码或修改第三方资料。

组件检查使用本机 Chrome 自动化与模拟视口，包含键盘、焦点、滚动恢复、背景点击边界、减少动态效果及自动化可访问性扫描。它不等于真实手机测试、全浏览器兼容性测试或全 WCAG 认证。应用整体验证见 [验收记录](../docs/design/ui-refactor-validation.md)；提示词里的验收列表是后续实施与回归检查目标。

后续每次新增资料都应记录当时读到了什么；热度数字变动、来源结构改变、许可不清、运行效果不符合任务时，应重新评审。保留未采用的理由，比持续增加相近的提示词数量更有用。
