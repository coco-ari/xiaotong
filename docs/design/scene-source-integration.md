# 模块接口接入操作说明

首页已有模块、规则、人物、背景和文案配置。服务端接入器负责定时读取业务 JSON 接口，将业务字段转为场景摘要。整体展示流程见 [模块场景设计](module-scenes.md)。

当前没有配置真实业务接口。生产环境继续使用明确标注的演示摘要；模拟上游只用于独立测试。接入器只更新首页人物场景摘要，理财持仓、收益曲线、资讯文章仍是原来的演示内容，需要另外接入对应完整业务数据。

## 1. 准备业务接口

目前支持固定 HTTPS 地址的 GET JSON 接口。本机联调允许 `localhost`、`127.0.0.1` 和 `[::1]` 的 HTTP。请求不跟随重定向，认证请求头从服务进程环境变量读取。

理财接口示例：

```json
{
  "code": 0,
  "data": {
    "todayProfit": -15,
    "totalProfit": 12680.52,
    "updatedAt": "2026-10-13T12:00:00+08:00"
  }
}
```

这是接口格式示例，日期必须替换为业务数据实际产生时间。缓存或历史报表保留原时间，不能改为抓取时间。接口只返回日期、缺少产生时间，或需要 POST、签名、OAuth 刷新、分页聚合时，应在业务侧转换后写入现有 `POST api/scene-data/:sourceId`，或另写对应接入器。

## 2. 配置映射

将 [配置样例](../../examples/scene-sources.example.json) 复制到运行数据目录的 `state/scene-sources.json`，替换 `url`、字段路径和认证环境变量名。这个目录已被 Git 忽略。不要把私人 URL、密钥或真实接口返回内容写进公开仓库。

配置默认从当前 `DATA_DIR` 下读取，也可通过 `SCENE_SOURCES_FILE` 指定绝对路径。没有配置文件时不发起采集；文件格式错误会阻止启动并报出配置错误。文件和环境变量变更在重启服务后生效。

| 配置 | 用途与约束 |
| --- | --- |
| `id` | 首页模块的数据源标识，例如 `finance`、`feed`、`reading-plan`；同一源只能有一个接入器 |
| `url` | 固定业务接口地址；不允许 URL 用户名、密码或片段 |
| `intervalSeconds` | 每次请求结束后的等待时间，15–86400 秒，默认 60 秒 |
| `timeoutMs` | 包含响应正文的超时，500–30000 毫秒，默认 10000 毫秒 |
| `headers` | 请求头及其环境变量引用；示例为 `Authorization` 加 `Bearer ` 前缀 |
| `readyWhen` | 可选业务成功条件，按路径读取后严格等值比较；数字 `0` 与文字 `"0"` 不相等 |
| `fields` | 1–20 个摘要字段，各自包含 `path` 和 `type` |
| `asOf` | 必填的上游产生时间路径和格式，支持 `iso`、`milliseconds`、`seconds` |

路径采用点分隔，例如 `data.todayProfit`、`items.0.count`；只读取对象自身字段。字段类型支持 `number`、`boolean`、`string`，以及显式将十进制文本转数字的 `numericString`。空白、`null`、千分位、带单位文字不会被当成零收益。

最多配置理财、资讯及另外 8 个自定义源。每份响应最多 256 KiB。多个源独立采集，单个慢接口不会阻塞其他源，同一个源不会重叠请求。

## 3. 检查后启用

在项目目录执行：

```sh
npm run scene:check -- state/scene-sources.json
npm run scene:check -- state/scene-sources.json --probe
```

第一条只校验配置；第二条读取实际接口并验证字段映射，不修改摘要、人物配置或收藏。两条命令都需要相同的认证环境变量。输出不包含密钥、接口地址、响应正文或收益数值。

探测通过表示协议和映射可用；输出的数据时间仍需符合模块有效期与今天的上海日期，过期数据会正确展示默认形象。

Linux 服务可通过 systemd drop-in 的 `EnvironmentFile` 加载本机凭据文件，按现有部署用户设置权限；文件中设置 `FINANCE_API_TOKEN=实际令牌`。不要在前端设置页填写密钥。配置准备好后重启现有 `lifehub-planner.service`；`DATA_DIR` 和原私人入口保持不变。

服务监听后立即采集一次，然后按设定间隔采集。首页每 30 秒读取摘要，切回前台也会刷新。首次配置真实源时先展示默认形象，收到可用数据后再切换。

## 4. 绑定首页模块

在「设置 → 人物与模块场景」中选择模块，让“数据源标识”与配置 `id` 相同，并按业务需要设置有效期、条件顺序及左侧文案。例如：

- `todayProfit > 0`：开心人物、暖阳背景、`今天赚了 {{todayProfit:absMoney}} 元`。
- `todayProfit < 0`：陪伴人物、雨天背景、`今日收益 {{todayProfit:money}} 元`。
- `todayProfit === 0`：平静人物与背景。
- 默认状态：阅读人物与中性背景，使用不依赖接口变量的等待文案。

资讯模块可将业务返回的未读条数映射为 `newItems`。新模块按同样方式映射自己的字段，首页无需新增判断分支。

同一个数据源应选择自动采集或业务主动推送其中一种接入方式，避免两方互相覆盖。移除自动采集配置不会清除已保存摘要；旧摘要随后按有效期失效，不会重新变成演示盈利。若希望立即停用该模块，可在设置里关闭它。

## 故障与验收

超时、HTTP 错误、业务失败、类型不符、缺少字段、无效或未来时间均保存错误状态并清空旧数值；下一轮成功后自动恢复。旧日期或超过模块有效期的数据保留原时间，由规则引擎判为不可用。日志只记录源标识与固定诊断信息。

在开发项目目录运行 `npm run scene:verify`，可在临时目录、随机本机端口完成模拟上游的实际 HTTP 联调，包括盈利、亏损、持平、旧报表、业务失败、字段错误和服务错误；不会访问生产入口或修改个人运行数据。`npm test` 包含同一组验证及整个项目回归。

2026-10-13 验收：项目 49 项测试通过，接入器相关 16 项包含在其中；生产构建成功。Chromium 的 393px 视口通过盈利、亏损、旧报表、服务故障和恢复持平五种状态验证，使用实际定时采集、持久化、HTTP 读取和页面展示，未拦截浏览器接口。五种状态的人物、背景和文案一致，未出现横向溢出或页面脚本错误。上游数据为独立模拟数据，这不代表已接入真实账户。
